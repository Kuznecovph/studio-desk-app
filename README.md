# Studio Desk

Минималистичный одностраничный реестр коммерческих фото- и видеопроектов. Работает как статический сайт на GitHub Pages. Без сборки, сервера, npm, сторонних JS-библиотек и подписок.

## Что умеет

- Обзор на 14 дней: ближайшие съёмки, задачи и подготовка за 3–7 дней.
- Проекты: стадии, заказчики, документы, сроки, следующие действия.
- Съёмки: календарь, адрес, время, техническое задание, источник.
- Задачи: срок, приоритет, статус, быстрое закрытие.
- Оплаты: договорные условия отдельно от подтверждённых сумм; расчёт календарных/рабочих дней от *фактической* даты события. Госпраздники РФ пока не учитываются.
- Локальный режим, экспорт/импорт JSON, CSV-экспорт, опциональная синхронизация с **приватным** GitHub-репозиторием.
- Корректная мобильная вёрстка; можно добавить на домашний экран.

## Быстрый старт на GitHub Pages

1. Создайте **новый публичный** репозиторий, например `studio-desk-app` (там будет **только код**).
2. Загрузите содержимое этого архива прямо в корень репозитория: `index.html`, `styles.css`, `app.js`, `favicon.svg`, `manifest.webmanifest`, `.nojekyll`, `README.md`.
3. Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)` → Save.
4. GitHub покажет адрес сайта вида `https://USERNAME.github.io/studio-desk-app/` после публикации.
5. Откройте сайт → Настройки → Импорт JSON → выберите полученный **отдельно** приватный файл с проектами. **НЕ добавляйте JSON с клиентами в публичный репозиторий.**

## Синхронизация между устройствами

1. Создайте **второй приватный** репозиторий на GitHub, например `studio-desk-data` (доступ — Private). Не путайте с публичным сайтом.
2. Settings (GitHub account) → Developer settings → Personal access tokens → Fine-grained tokens → Generate. Ограничьте токен одним приватным репозиторием, Contents: **Read and write**. Выберите короткий срок действия и храните токен как пароль.
3. В веб-приложении, в разделе «Настройки и синхронизация», введите ваш GitHub-логин, название **приватного** репозитория и токен.
4. На первом устройстве нажмите «Отправить в GitHub» — создастся `data/registry.json` в приватном репозитории.
5. На другом устройстве откройте сайт и нажмите «Загрузить из GitHub», затем при изменениях «Отправить в GitHub».
6. Перед заменой данных делайте экспорт JSON. Приложение проверяет SHA при записи и **блокирует перезапись**, если удалённый файл изменился.

Внимание: токен живёт **только в памяти вкладки** и пропадает после обновления страницы, поэтому его нужно вводить снова. Это преднамеренное ограничение безопасности. Данные в localStorage доступны только этому браузерному профилю/устройству и могут исчезнуть при очистке браузера. Между устройствами данные сами по себе не синхронизируются.

Приложение не подключено напрямую к Google Календарю и не синхронизирует Google Таблицы автоматически. Данные нужно заносить вручную, импортировать JSON или синхронизировать через GitHub. Для утренней задачи ChatGPT должен иметь доступ к приватному репозиторию через подключение GitHub; доступ инструментов в запланированных запусках нужно проверить отдельно.

## Безопасность

- **Никогда** не коммитьте реальные данные (`.json` с клиентами), токены или пароли в публичный репозиторий сайта.
- Не вставляйте токен в URL и не пересылайте его третьим лицам.
- Токен передаётся браузером напрямую к `api.github.com` только после нажатия синхронизации.
- Если возникло подозрение на компрометацию, отзовите токен в настройках GitHub.
- Локальный JSON с коммерческой информацией храните в защищённой папке.
- В приложение не встроены аналитика и сторонние скрипты.

## Условия и ограничения

Это рабочий MVP, а не бухгалтерская система: условия договоров и расчётные сроки не доказывают оплату; статус «Не проверено» не означает задолженность. Расчёт рабочих дней исключает субботу и воскресенье, но пока не учитывает праздничные и переносные дни России. История изменений и многостороннее объединение конфликтующих правок отсутствуют; используется ручной pull/push и защита SHA.

## Локальная проверка

Откройте папку через любой статический сервер: `python3 -m http.server 8080`, затем `http://localhost:8080`. Для работы через GitHub Pages сервер не нужен.
